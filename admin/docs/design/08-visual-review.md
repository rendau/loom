# 08 — Visual Review

Дата: 2026-08-25. Аудит **живого рендера** после этапов 1–4 (не билд-лог и
не предположения): полный локальный стенд — Postgres + registry в docker,
artifact-сервер и control plane локально, EXECUTOR=docker, три реальных
дага (demo_etl со стримом и расписанием */5, demo_fail с ретраем и
провалом валидации, demo_env с переменными/секретом), реальные раны всех
статусов, живые логи.

## Метод

1. **Level A/B — Browser pane**, тёмная тема, вьюпорт 1180×900: ручной
   проход всех страниц и сценария J1 (провал → автовыбор → лог → ретрай),
   J5 (фильтры из URL), карточка дага (обе табы), env, обзор.
2. **Level C — механический sweep** (playwright-core из глобального
   рантайма): 12 страниц × 4 вьюпорта (1024×768, 1180×900, 1280×800,
   1512×944), светлая тема (headless-дефолт — обе темы покрыты).
   Проверки: горизонтальный оверфлоу страницы, элементы за пределами
   вьюпорта (вне scroll-контейнеров), ошибки консоли. Bundled-скрипт скила
   frontend-visual-qa не умеет авторизацию через localStorage — использован
   эквивалентный тонкий скрипт с теми же проверками (в scratchpad, в репо
   не кладётся).

## Результат sweep

**CLEAN** — на всех 48 комбинациях страница×вьюпорт: ноль горизонтального
оверфлоу, ноль элементов за вьюпортом, ноль ошибок консоли. Главный
критерий редизайна (C3: вписаться в 1180) выполняется механически.

Покрытые страницы: обзор, список дагов, карточка дага (обзор+схема),
список ранов (+фильтр failed), ран с инспектором (лог упавшего таска),
ран с env-табой, полноэкранный лог, env, пулы, пользователи.

## Найдено и исправлено по ходу аудита

1. **Empty state при ошибке загрузки** — «Дагов пока нет» показывался
   одновременно с алертом ошибки (вводит в заблуждение). Исправлено:
   при loadError пустое состояние не рендерится (`/dags`, `/runs`).
2. **Граф: `upstream_failed` рисовался warning-жёлтым** (в бейджах уже был
   приглушён) — на светлой и тёмной теме отвлекал от реально упавшего
   узла. Исправлено: приглушённый нейтральный, без цветной заливки.
3. **Цвет выделения primary = зелёный success** — выбранный failed-таск
   выглядел «успешным» (зелёная рамка узла, зелёное имя в списке).
   Исправлено: выделение — нейтральная внешняя рамка text-highlighted у
   узла графа и chevron-маркер в списке; статусные цвета не искажаются.
4. **Таба Env с бейджем «0»** — шум у тасков без привязок. Исправлено:
   таба скрывается, когда привязок нет.

## Проверено визуально (ок)

- Плотность таблиц: строки py-1.5, страница рана с графом, списком тасков
  и инспектором с логом умещается на 1180×900 без вертикального скролла
  до инспектора.
- Обе темы: контраст статусных бейджей, лог-вьювера, графа — читаемо.
- Live-состояния: тикающая длительность running-рана в списках,
  spin-иконки только у живых объектов, «след.: через N мин» у расписаний.
- Относительное время: «только что / N мин назад / сегодня …» + абсолют
  в tooltip; «Дата данных» — абсолютная (короткий формат).
- Логи: разбор logfmt, уровни, источники (log/srv), фильтры, перенос,
  скачивание; счётчик строк «6 / 6».
- Модалки подтверждений: ретрай перечисляет сбрасываемый downstream-подграф.
- Пустые состояния с действием (даги, раны, пулы).

## Не покрыто (осознанно)

- Мобильные вьюпорты — инструмент настольный, минимальный поддерживаемый
  1024 проверен.
- Таба «Артефакты» и блок «Хранилище» — не существуют до API (design/07).
- Клавиатурная навигация по списку тасков (стрелки) — не реализована в
  этапах 1–4, отмечена в 09-ux-review.
