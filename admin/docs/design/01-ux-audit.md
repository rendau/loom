# 01 — UX Audit

Оценка текущей админки по эвристикам Nielsen, ментальным моделям и
принципам операционных интерфейсов. Контекст: вьюпорт ~1180px, 27 дагов,
4–10 операторов, главная работа — диагностика ранов.

Северити: **Critical** — блокирует/сильно замедляет основную работу;
**High** — заметно мешает или основная задача не поддержана; **Medium** —
трение; **Low** — полировка.

---

## C1. Страница рана не построена вокруг диагностики — Critical

**Евристика:** соответствие ментальной модели; иерархия информации.

**Свидетельство:** `pages/runs/[id]/index.vue` — вертикальная простыня из
четырёх независимых блоков: мета-грид → граф → таблица «Таски» (8 колонок)
→ «Значения» → «Попытки» (8 колонок). Таблица «Попытки» дублирует
«Таски» почти полностью (таск, статус, времена, память, лог) — при том,
что >1 попытки у таска — редкость. Лог открывается slideover'ом поверх.

**Влияние:** разбор провала — главный сценарий — требует: проскроллить до
таблицы, найти глазами failed-строку, понять, где лог — в «Тасках» или в
«Попытках», открыть slideover, закрывающий контекст. Данные об одном
таске размазаны по трём местам (граф, две таблицы). На маленьком экране —
ещё и горизонтальный скролл таблиц.

**Рекомендация:** master-detail: компактный список тасков + инспектор
выбранного таска (лог / попытки / артефакты / значения / env в табах).
Отдельную таблицу «Попытки» уровня рана — убрать (попытки живут внутри
таска). Прямой путь «ран открыт → упавший таск выбран → лог виден».

## C2. Нет значений переменных/параметров контекста рана — Critical

**Евристика:** visibility of system status; recognition over recall.

**Свидетельство:** на странице рана есть params (свёрнутый JSON), но нет
того, с какими переменными/секретами реально запускались таски. Привязки
(env → имя) есть только в таблице тасков манифеста на карточке дага.

**Влияние:** «упало из-за конфига?» — самый частый вопрос диагностики —
требует ходить в `/env` и гадать, не поменяли ли значение после запуска.

**Рекомендация:** блок «Окружение рана» (или таба инспектора таска):
env-имя → тип → источник (скоуп) → значение переменной (секрет — только
имя). Честный вариант — снапшот на момент launch: **требование к API**.

## C3. Таблицы не влезают в 1180px — Critical

**Евристика:** гибкость и эффективность; плотность без скролла.

**Свидетельство:** `/dags` — 6 информационных колонок (включая широкие
«Образ» и «Расписание» с двумя строками) + до **8 icon-действий** в каждой
строке. UTable по умолчанию `whitespace-nowrap` → горизонтальный скролл.
На странице рана таблицы по 8 колонок с datetime в двух колонках.

**Влияние:** пользователь прямо называет это главным раздражителем.
Горизонтальный скролл в таблице = невидимые данные и действия.

**Рекомендация:** бюджет ширины каждой таблицы ≤1100px; редкие колонки —
убрать в детальные страницы/инспектор; действия — свернуть в меню «⋯»;
длинные строки (image, digest, id) — truncate + copy. Правило: две
datetime-колонки в одной таблице не живут.

## H1. Список дагов: 8 действий-иконок в строке — High

**Евристика:** error prevention; recognition; aesthetic & minimalist.

**Свидетельство:** `/dags` строка: play, backfill, расписание, sync,
auto-update-toggle, pause, delete (+ tooltip на каждом). Смысл понятен
только по ховеру; «удалить» — в одном ряду с «запустить».

**Влияние:** случайные клики, зрительный шум, ширина. Для user'а без прав
набор кнопок меняется от строки к строке — таблица «прыгает».

**Рекомендация:** inline остаётся только частое (запуск, пауза), остальное
— в UDropdownMenu «⋯» с подписями. Delete — только в меню, визуально
отделён. То же в navbar карточки дага (сейчас там 8 иконок).

## H2. Мониторинг дага не поддержан — High

**Евристика:** ментальная модель задачи «мониторю даг».

**Свидетельство:** карточка дага показывает манифест (статику), но не
показывает ни одного рана, ни метрик: нет истории длительностей, нет
памяти по таскам, нет «жирных» тасков. Ссылка «Раны дага →» уводит в
общий список.

**Влияние:** задачи «мониторю потребление памяти, время выполнения,
жирные таски у дага» требуют ручного обхода ранов по одному.

**Рекомендация:** карточка дага = операционная сводка: последние раны
(статус-стрип + список), тренд длительности, топ тасков по времени/памяти
(агрегат — **требование к API**; без него — хотя бы по последнему рану).

## H3. Артефакты недоступны — High

**Свидетельство:** артефакты — центральное понятие loom («данные текут
персистентными стримами»), но в UI их нет вообще: ни списка, ни
скачивания, ни размеров.

**Влияние:** задача «скачать/посмотреть артефакт между тасками» решается
только через kubectl/прямой доступ — мимо продукта.

**Рекомендация:** таба «Артефакты» в инспекторе таска (имя, размер,
статус стрима, превью первых КБ, скачивание) + требования к API
(list/read через gateway с auth).

## H4. Дашборд не отвечает «что требует внимания» — High

**Евристика:** дашборд должен отвечать «what needs my attention».

**Свидетельство:** 4 стат-карты («Дагов: 27» — декоративная метрика),
activity bars за 2 недели, «Последние провалы» списком **run_id**
(нечитаемый uuid) без имени дага, без «когда» относительного, без причины.
Ближайшие запуски и пулы — полезны, но равноправны с декором.
Volume artifact-сервера отсутствует.

**Влияние:** оператор утром не видит: что упало с прошлого раза, что
сейчас выполняется и не зависло ли, есть ли риск по месту на volume.

**Рекомендация:** иерархия: (1) провалы, требующие разбора (даг + таск +
когда + переход к логу); (2) выполняется сейчас (с длительностью и
сравнением с типичной); (3) ближайшие запуски / пулы; (4) ёмкость
volume (**требование к API**). Декоративные счётчики — убрать или сжать.

## H5. Список ранов: нет живости и слабые фильтры — High

**Свидетельство:** `/runs` не обновляется сам (в отличие от рана и
дашборда); фильтр по дагу — свободный текст (при 27 дагах просится
селект); нет `logical_date` (для backfill-ранов «Создан» неинформативен);
нет быстрых пресетов «провалы за сегодня».

**Влияние:** слежение за парком ранов — через F5; поиск нужного
backfill-рана мучителен.

**Рекомендация:** авто-поллинг как на дашборде; фильтр по дагу — селект с
поиском; статусы — быстрые чипы со счётчиками; колонка «Дата данных» для
schedule/backfill; сохранение фильтров в URL (как уже сделано в `/env`).

## M1. Непоследовательный поллинг и «кнопка обновить» — Medium

30с на дашборде, 3с на ране, ничего на списках. Кнопка refresh в каждом
navbar — костыль для отсутствия поллинга. Рекомендация: единый composable
(`usePolling`) с паузой на скрытой вкладке; кнопку оставить, но одну
семантику везде.

## M2. Slideover лога закрывает контекст — Medium

Лог открывается поверх графа/таблиц (max-w-5xl на 1180 — почти весь
экран). Смотреть лог и статусы тасков одновременно нельзя. Рекомендация:
лог — таба инспектора таска в потоке страницы; полноэкранный маршрут
остаётся для «только лог».

## M3. Значения (XCom) — таблица уровня рана — Medium

Значения принадлежат таскам; отдельная таблица дублирует колонку «Таск» и
раздувает страницу. Рекомендация: в инспектор таска; сводно — счётчик.

## M4. `upstream_failed` окрашен как warning — Medium

**Свидетельство:** `utils/status.ts`: `upstream_failed → warning`, подпись
«провал зависимости». Таск не выполнялся, но выглядит как «почти ошибка»;
в графе оранжевые узлы отвлекают от единственного реально упавшего.
Рекомендация: нейтральный/приглушённый стиль (это следствие, не причина);
в графе — визуально гасить.

## M5. Datetime-колонки съедают ширину — Medium

`formatDateTime` («25.08.2026, 14:03») по 2 шт. на таблицу. Для
операционных списков важнее «когда относительно сейчас» (5 мин назад) +
абсолют в tooltip/детали. Рекомендация: относительное время в списках,
абсолютное — в инспекторе/деталях.

## M6. История регистраций — таблица на карточке дага — Medium

Пять колонок ради редких событий; ошибка регистрации — мелкой строкой.
Рекомендация: компактный timeline/список из 2–3 последних с раскрытием,
ошибки — заметно.

## A1. Icon-only кнопки без aria-label — Medium (a11y)

UButton с иконкой без label и без `aria-label` (tooltip — визуальный).
Скринридер читает «button». Рекомендация: aria-label на все icon-only
кнопки (у Nuxt UI есть проп `aria-label`), фокус-стили не трогать (есть).

## A2. Цвет как единственный сигнал в графе — Low (a11y)

Узлы графа различаются только цветом рамки/заливки (есть title-tooltip).
Подпись статуса под именем таска частично спасает. Рекомендация: сохранить
текстовую подпись статуса в узле всегда (уже есть) + иконку статуса.

## L1. Пагинация по центру на 30 строк — Low

При 27 дагах пагинация почти не нужна; занимает вертикаль. Рекомендация:
компактно в правый край подвала таблицы; page_size больше.

## L2. Мелкие несоответствия — Low

- «Ран» назван и «Создан», и «Создана» (попытки) — ок, но выравнять
  терминологию «попытка/ретрай».
- Заголовок страницы рана — голый uuid; имя дага важнее.
- В `/runs` иконка «параметры» (braces) без числа/подсказки что внутри.
- Dashboard: «Последние провалы» — run_id вместо имени дага (см. H4).
