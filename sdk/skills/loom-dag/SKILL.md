# loom — написание дагов на Go

Даг — обычный Go-бинарник на `github.com/rendau/loom/sdk`, упакованный в docker-образ.
Один образ может нести несколько дагов. Управляющий слой (control plane) запускает
**тот же образ** отдельным контейнером на каждый таск.

Справочники (читай при необходимости, не грузи заранее):

- `references/api.md` — полный справочник API, CLI, env-контракта и манифеста;
- `references/pitfalls.md` — **подводные камни**; читай, если правишь существующий даг
  или разбираешь падение;
- `references/patterns.md` — **проверенные приёмы** (не требования SDK): раскладка
  репозитория, потоковый формат обмена, стриминг вместо материализации, параллельность
  внутри таска, конфигурация, логи, сборка и выкладка;
- `references/operations.md` — жизненный цикл дага на control plane: регистрация,
  шаблоны и инстансы, расписание, переменные, ретраи, retention, отладка.

## Модель: проект → шаблон → даг-инстанс

| Сущность | Что это |
|---|---|
| **Проект** | docker-образ, зарегистрированный на control plane |
| **Шаблон** | один `*loom.DAG`, объявленный в бинарнике образа (`loom.Main(a, b)` → два шаблона) |
| **Даг** | инстанс шаблона: своё расписание, пул, переменные и секреты. Идентификатор составной — `проект/имя` |

Инстансы одного шаблона различаются **настройками и значениями переменных, а не кодом**
(даг на магазин: `SHOP=mechta` и `SHOP=technodom`). Поэтому:

- **не хардкодь конфигурацию инстанса в коде** — выводи её в `loom.Variable`/`loom.Secret`;
- расписание (`schedule`), `catchup`, пул слотов и пауза **в коде не задаются вообще** —
  ими управляет админка. В SDK из «настроек дага» остался только `MaxActiveRuns`.

## Скелет

```go
package main

import (
	"bufio"
	"context"
	"fmt"
	"time"

	loom "github.com/rendau/loom/sdk"
)

func main() {
	// main() только объявляет даги — никаких подключений к БД, чтения
	// конфигов и сетевых вызовов: этот же код исполняется при describe
	loom.Main(newOrdersETL())
}

func newOrdersETL() *loom.DAG {
	dag := loom.New("orders_etl", loom.MaxActiveRuns(1))

	extract := dag.Task("extract", func(ctx context.Context, rt *loom.Runtime) error {
		out, err := rt.Output("orders") // io.WriteCloser
		if err != nil {
			return err
		}

		for i := range 1000 {
			if _, err = fmt.Fprintf(out, "order-%d\n", i); err != nil {
				return err
			}
		}

		rt.Log().Info("extracted", "count", 1000)
		return nil // успех таска = commit всех его выходов
	}, loom.Retries(2), loom.Timeout(30*time.Minute))

	dag.Task("load", func(ctx context.Context, rt *loom.Runtime) error {
		in, err := rt.Input("extract", "orders")
		if err != nil {
			return err
		}
		defer in.Close()

		sc := bufio.NewScanner(in)
		sc.Buffer(make([]byte, 0, 64*1024), 8*1024*1024) // строки длиннее 64KB — иначе ErrTooLong
		count := 0
		for sc.Scan() {
			count++
		}
		if err = sc.Err(); err != nil {
			return err
		}

		rt.Log().Info("loaded", "count", count)
		return nil
	}, loom.After(extract))

	return dag
}
```

Проверка без docker и сервера — локальный прогон (таски горутинами, артефакты файлами
в `.loom/runs/<run-id>/`, остаются после рана):

```bash
go run . describe                        # каталог образа: манифесты всех дагов
go run . run                             # прогон целиком
go run . run --dag=orders_etl            # если дагов в образе несколько
go run . run --params='{"day":"2026-01-01"}'
```

## Жёсткие правила

1. **`main()` не делает ничего, кроме объявления дагов.** Тот же бинарник запускается
   в режиме `describe` при регистрации образа и в режиме `run --task` на каждый таск —
   любые side-effect'ы конструктора (dial БД, чтение файлов, `log.Fatal` на пустой env)
   ломают регистрацию и каждый запуск. Подключения открывай **внутри `TaskFn`**.
2. **С внешним миром по данным таск общается только через `Runtime`.** Это условие
   переносимости между локальным и распределённым режимами.
3. **Commit выходов привязан к результату таска:** `return nil` — все выходы committed,
   ошибка или паника — aborted. `out.Close()` опционален и **не коммитит** (лишь запрещает
   дальнейшую запись). Никогда не глотай ошибку записи — иначе закоммитишь битые данные.
4. **Буферизованный писатель обязан быть сброшен `Flush()` в успешной ветке.**
   Хвост, оставшийся в `bufio.Writer`, не попадёт в артефакт, а loom закоммитит
   обрезанные данные как валидные. `defer w.Flush()` не годится — его ошибка теряется.
5. **`rt.Input`/`rt.PullValue` доступны только для объявленных прямых зависимостей**
   (`After`/`AfterStreamed`). Транзитивная зависимость не считается — объявляй ребро явно.
6. **Таск обязан быть идемпотентным**: ретрай, `RetryTask` из админки и backfill выполняют
   его повторно. Побочные эффекты — через upsert / уникальный ключ / `logical_date`.
7. **Уважай `ctx`**: по нему приходит `Timeout` и остановка рана. Все блокирующие вызовы —
   с контекстом.
8. **Никакого общего состояния между тасками**: в проде это разные контейнеры на разных
   узлах. Общая память и `/tmp` есть только в локальном режиме — там таски горутины
   в одном процессе, и «локально работает, в проде нет» рождается именно здесь.
9. **Имена** дага, таска и артефакта: `^[a-z0-9][a-z0-9_-]{0,62}$` (нижний регистр).
   Имя env-переменной: `^[A-Za-z_][A-Za-z0-9_]{0,127}$` и **не начинается с `LOOM_`**.

## Данные между тасками

### Артефакты — основной канал

Артефакт — персистентный стрим со скоупом **на попытку**: `(run_id, task, attempt, name)`.

```
writing ──commit──▶ committed   (читатели дочитают до конца и получат EOF)
   └─────abort───▶ aborted      (читатели получат ошибку)
```

- Это **не пайп**: данные лежат на диске, писатель не ждёт читателя, а ретрай получателя
  просто читает стрим заново с нуля — перезапускать отправителя не нужно.
- `EOF` у читателя означает «отправитель успешно завершился, данные полны».
- Ретрай отправителя пишет новой попыткой (`attempt+1`), прошлые данные не трогаются.
- Читатель, открывшийся раньше писателя, ждёт появления артефакта; догнавший хвост —
  ждёт новых данных.
- Не создать артефакт — нормально: читатель разблокируется по завершении попытки
  отправителя и получит `NOT_FOUND`. То есть **опциональный выход требует
  явного контракта** — либо пиши всегда (пусть пустым), либо передавай признак значением.

### Значения (аналог XCom) — только мелочь

`rt.PushValue(key, v)` / `rt.PullValue(task, key, &dest)` — счётчики, id, статусы.
JSON, **лимит 64KB**, повторный push по тому же ключу перезаписывает. Данные —
только артефактами.

### Рёбра

| Опция | Семантика |
|---|---|
| `loom.After(dep)` | получатель стартует **после успеха** `dep` |
| `loom.AfterStreamed(dep)` | получатель стартует **одновременно** с `dep` и читает по мере записи |

`AfterStreamed` — opt-in ускорение для длинных конвейеров. Падение отправителя abort'ит
его артефакты, и стримовый читатель падает вместе с ним: держи его `Retries`
не меньше, чем у отправителя.

## Параметры рана и «дата данных»

```go
var p struct {
	Day   string `json:"day"`
	Force bool   `json:"force"`
}
if len(rt.Params()) > 0 {          // BindParams на ране без параметров вернёт ошибку
	if err := rt.BindParams(&p); err != nil {
		return err
	}
}

day := rt.LogicalDate()             // тик расписания у cron/backfill, момент триггера у ручного
```

**Партиционируй по `rt.LogicalDate()`, а не по `time.Now()`** — иначе catchup и backfill
перезальют сегодняшний день вместо исторического.

## Переменные и секреты

```go
dag.Task("sync", syncFn,
	loom.Variable("PG_DSN", "pg_dsn", "DSN основной БД, формат postgres://…"),
	loom.Secret("S3_KEY", "s3_key", "ключ доступа к бакету выгрузок"),
)
```

Значение читается обычным `os.Getenv("PG_DSN")` **внутри таска**. Описание (третий
аргумент) уезжает в манифест и показывается в админке тому, кто заполняет значение, —
**пиши его всегда**.

- Отсутствующее на момент запуска имя валит попытку (`launch_failed`), поэтому
  объявляй только то, что действительно нужно этому таску.
- Скоуп значения (глобальный / проектный / дага) выбирается в админке; более узкий
  перекрывает более широкий.
- **В локальном режиме инъекции нет** — задавай переменные окружением процесса:
  `PG_DSN=... go run . run`.
- Секреты не логировать. `rt.Log()` уходит в общий лог таска, видимый в админке.

## Ретраи, таймаут, ресурсы

```go
dag.Task("load", loadFn,
	loom.After(transform),
	loom.Retries(3),                    // всего попыток retries+1; потолок на сервере — 100
	loom.RetryDelay(time.Minute),       // база; удваивается с каждой попыткой, потолок 30 мин
	loom.Timeout(2*time.Hour),          // ctx отменяется; зависшую попытку добьёт control plane
	loom.Resources(loom.ResourceSpec{   // нотация k8s quantities; в docker/локально частично игнорируется
		CPURequest: "500m", MemoryRequest: "512Mi", MemoryLimit: "2Gi",
	}),
	loom.Priority(10),                  // приоритет в очереди пула
)
```

- Без `RetryDelay` пауза — 30 секунд.
- `Resources` из кода — **рекомендация**: непустой оверрайд из админки приоритетнее
  по-полево и подхватывается ретраями без перерегистрации.
- `MemoryLimit` мал → попытка умрёт `OOMKilled`. Пик памяти попытки виден в админке.

## Чек-лист перед сдачей дага

- [ ] `go run . describe` — валидный каталог, у каждого дага непустой `tasks`;
- [ ] `go run . run` проходит локально; в `.loom/runs/<id>/` лежат ожидаемые артефакты;
- [ ] `main()` без side-effect'ов, соединения открываются внутри тасков;
- [ ] каждый таск идемпотентен и партиционируется по `rt.LogicalDate()`;
- [ ] у каждого `rt.Input` есть соответствующее ребро `After`/`AfterStreamed`;
- [ ] ошибки записи в выход не проглочены, `return err` возвращается наверх;
- [ ] буферизованный писатель сбрасывается `Flush()` перед `return nil`;
- [ ] длинные строки: `bufio.Scanner` с увеличенным `Buffer` или `bufio.Reader`;
- [ ] все внешние адреса/креды вынесены в `Variable`/`Secret`, **у каждого непустое
      описание** (проверяется по выводу `describe`), и значения заведены на control
      plane **до** выкатки образа;
- [ ] `Timeout` проставлен там, где внешняя система может подвиснуть;
- [ ] `Retries` у стримового читателя не меньше, чем у его отправителя;
- [ ] итоговая строка лога называет приёмник и все счётчики, включая нулевые;
- [ ] клиенты внешних систем — с явными таймаутами соединения и лимитом пула;
      JSON, если он есть, — стандартным `encoding/json` (см. `references/pitfalls.md`);
- [ ] Dockerfile: `ENTRYPOINT ["/app/dag"]` без `CMD` (control plane дописывает
      `describe` / `run` аргументом).
