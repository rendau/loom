# 07 — Implementation Plan

Инкрементальная миграция: каждый этап — рабочая админка, деплоится
независимо. Бэкенд не трогаем; всё, что требует API, вынесено в раздел
«Требования к API» и имеет UI-fallback либо откладывается.

> **Статус (2026-08-25): этапы 1–5 реализованы.** Этапы 1–4 — фронт на
> существующем API; этап 5 — вместе с реализацией всех требований к API
> (P1+P2, см. ниже): артефакты через gateway (список, скачивание, превью),
> статистика хранилища, env-снапшот рана (`run_env`, upsert при launch),
> `GetDagStats`, `last_runs` в ListDag, `CountRun`, таск-виновник в
> `recent_failures`. Проверено на живом стенде (08-visual-review,
> 09-ux-review).

## Требования к API (не реализуем — только контракт-пожелания)

Приоритет P1 — разблокирует заявленные владельцем задачи; P2 — качество.

1. **P1. Артефакты через gateway** (`server_v1.ArtifactService`, проксирует
   artifact-сервер с auth админки):
   - `ListRunArtifacts(run_id) → [{task, attempt, name, size_bytes,
     state: writing|committed|aborted, created_at}]`;
   - HTTP-эндпоинт скачивания `GET /v1/run/{run_id}/artifact/{task}/{attempt}/{name}`
     (stream, Content-Disposition; auth — тот же bearer) — для скачивания
     браузером и превью (`Range`/`?limit_bytes=` для первых N КБ).
2. **P1. Хранилище артефактов**: `GetStorageStats → {data_dir: {used,
   total}, log_dir: {used, total}}` (df по каталогам artifact-сервера;
   опционально разбивка по дагам — some day).
3. **P1. Env-снапшот рана**: при launch фиксировать резолв переменных
   (имя, скоуп-источник, значение) и имена секретов (без значений);
   отдавать в `RunGetRep` (или отдельным `GetRunEnv`). Секретные значения
   не хранить и не отдавать никогда.
4. **P2. Агрегаты дага**: `GetDagStats(dag_name, last_n_runs) → по таскам:
   {avg/max duration_sec, avg/max peak_memory_bytes}` + по ранам
   {duration, finished_at, status} — для «жирных тасков» и тренда без
   N+1 запросов.
5. **P2. Последние статусы ранов в ListDag**: `last_runs: [status × 5]`
   на каждый даг (статус-стрип).
6. **P2. Счётчики статусов**: `CountRuns(dag_name?) → {running, failed,
   success, canceled}` для чипов `/runs` (или в ListRun-ответ).
7. **P2. Причина провала рана**: в `recent_failures` дашборда добавить
   `task`, `exit_reason` первого упавшего таска.

## Риски

- Master-detail на 1180px: лог в нижней панели ~50vh — мало? Митигция:
  кнопка «на весь экран» всегда на виду; высота панели — resizable
  (UDashboardPanel/resizable или простой drag) — nice-to-have.
- Автовыбор failed-таска может «прыгать» при поллинге (появился более
  ранний failed) — фиксировать выбор после первого автовыбора.
- Fallback «текущие значения переменных» может ввести в заблуждение —
  обязательна явная пометка; снапшот (API №3) закрывает риск.
- Удаление колонок из /dags — если кому-то нужны были SDK/образ в
  списке: они в карточке, один клик.
