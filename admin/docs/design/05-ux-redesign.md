# 05 — UX Redesign

Дизайн экранов в новой IA. Общие правила (действуют везде):

- **Бюджет ширины:** контент страницы вписывается в 1180px. Таблицы не
  дают горизонтальный скролл страницы; широкое (лог, граф) скроллится в
  своём контейнере.
- **Время:** в списках — относительное («5 мин назад», «вчера 14:03»),
  абсолютное — в tooltip и в деталях. Даты данных (logical_date) — всегда
  абсолютные.
- **Длинные строки** (image, digest, id): truncate середины/конца + копия
  по клику (CopyText). Полностью — только в деталях.
- **Статус:** всегда бейдж «иконка + подпись» (цвет вторичен).
  `upstream_failed` и `canceled` — приглушённые.
- **Действия:** ≤2 inline-кнопок на строку, остальное — меню «⋯» с
  подписями; разрушительные — внизу меню, отделены. Недоступные по правам
  действия не рендерятся.
- **Поллинг:** один composable; Обзор и списки — 10–15с, живой ран — 3с,
  пауза на скрытой вкладке. Кнопка «обновить» остаётся в navbar.
- **A11y:** каждая icon-only кнопка получает `aria-label`.

---

## 1. Обзор (`/`)

**Назначение:** ответить «что требует моего внимания» за 5 секунд.
**Главный вопрос:** есть ли провалы для разбора и здоровы ли текущие раны.
**Главное действие:** переход в проблемный ран (сразу к упавшему таску).

### Иерархия

1. **«Требует внимания»** — верхний блок во всю ширину:
   - Провалы (последние 24ч, потом «старее»): `даг · таск-виновник ·
     exit reason · когда` → клик = `/runs/<id>?task=<t>`. Если провалов
     нет — спокойная зелёная строка «Провалов нет», не пустая дыра.
   - Зависшее: running-раны с длительностью > max за неделю по этому
     дагу — «дольше обычного» (данные `dag_durations` уже есть).
2. **«Выполняется сейчас»**: компактные строки `даг · таск(и) running ·
   идёт N мин` (+бейдж live). Пусто — «Активных ранов нет».
3. Второй ряд (грид 2×2, компактный):
   - Активность за 2 недели (bars — оставить как есть);
   - Ближайшие запуски (как есть, +пометка paused);
   - Пулы: только когда busy>0 или slots=0 — иначе одна строка «свободны»;
   - **Хранилище артефактов**: занято / всего volume, тренд не нужен
     (*API-требование; до него блок скрыт*).
4. Счётчики-карточки текущего дашборда **убираются** (актив/за
   сутки/неделя/дагов). Их смысл переезжает: активные — блок 2, провалы —
   блок 1, «дагов 27» — не решение, а декор.

### Состояния

Loading — скелетоны блоков; error — alert с retry; пустая система (0
дагов) — onboarding-заглушка «Зарегистрируйте первый даг» + ссылка.

## 2. Даги (`/dags`)

**Назначение:** быстрый обзор парка (27 шт.) и вход в карточку.
**Главный вопрос:** какие даги в каком состоянии, когда следующие запуски.
**Главное действие:** открыть карточку; частое — запустить/пауза.

### Таблица (бюджет ~1100px)

| Колонка | Содержимое | ~px |
|---|---|---|
| Даг | имя (link, жирное) + бейджи `пауза`/`обновляется`/`auto` | 260 |
| Последние раны | статус-стрип: 5 квадратиков последних ранов (цвет+tooltip), клик → ран (*API-требование; до него — статус последнего рана*) | 120 |
| Расписание | cron моно + `catchup`; под ним «след: через 2ч» | 200 |
| Тасков | число | 60 |
| Обновлён | относительное время (это про образ; image/digest/SDK — в карточке) | 110 |
| Действия | ▶ Запустить (inline) + меню «⋯» | 90 |

Убраны из таблицы: «Образ», «SDK», «Создан» (переезжают в карточку).
Строка кликабельна целиком → карточка.

Меню «⋯»: Пауза/Снять, Расписание…, Backfill…, Обновить из registry,
Авто-обновление вкл/выкл, ── Удалить… (admin). Состав — по правам.

Сортировка по имени (дефолт); фильтр не нужен при 27 дагах, но лёгкий
поиск по имени в тулбаре — дёшев и полезен. Пагинация при 27 не
показывается (page_size 100).

Панель регистраций: активные — одна компактная строка-прогресс на
регистрацию; провалы — alert как сейчас (единственное место с причиной
до создания дага — сохранить).

### Состояния

Пусто — как сейчас («зарегистрируйте docker-образ», + кнопка). Loading —
skeleton rows. Ошибка загрузки — alert с retry (не тост: тост исчезает).

## 3. Карточка дага (`/dags/[name]`) — табы

Шапка: `← Даги / <имя>` · бейджи (пауза/обновляется) · ▶ Запустить ·
меню «⋯» (остальные действия, как в списке). Вместо 8 иконок.

### Таба «Обзор» (дефолт) — поведение дага

1. Строка контекста: расписание+catchup · след. запуск · лимит активных ·
   образ (truncate+copy).
2. **Последние раны** (10–20): `статус · триггер · дата данных · когда ·
   длительность · Σ память` → клик = ран. Мини-бар длительностей рядом
   (spark-столбики, ось — раны).
3. **Таски по ресурсам** («жирные таски»): таблица `таск · ср. длительность
   · пик памяти (ср./макс) · memory_limit · доля от лимита` — сортировка
   по памяти/длительности. (*API-требование агрегата; fallback — данные
   последнего завершённого рана с пометкой*).

### Таба «Схема» — как устроен

1. Граф (как сейчас).
2. Таблица тасков манифеста — сжать до: `таск · зависимости · ретраи ·
   таймаут · пул/приоритет · ресурсы · env` (бейджи привязок как сейчас);
   ширины хватает, т.к. нет соседних блоков.
3. История регистраций — компактный список (2–3 видимых + «показать все»):
   `статус · источник · когда · образ`, ошибка — раскрытая красная строка.
4. Служебное: digest, SDK, создан/обновлён — мелкий мета-грид внизу.

### Таба «Настройки» *(опционально, можно без неё)*

Расписание/catchup, auto-update, пауза — формой вместо модалок. Если
табу не делаем — модалки остаются из меню «⋯». Рекомендация: **без табы**
в первой итерации (модалки работают, риск ниже).

## 4. Раны (`/runs`)

**Назначение:** живой список выполнений + поиск конкретного рана.
**Главный вопрос:** что сейчас идёт / что упало / где ран за дату D.

### Тулбар

- Селект дага (searchable, 27 значений; `?dag=`);
- Чипы статуса со счётчиками: Все · Выполняются · Провалы · Успех ·
  Остановлены (счётчики — *API-требование*; без него просто чипы);
- Селект триггера (вручную/расписание/backfill) — редкий, в конец;
- Всё в URL (как в /env).

### Таблица (бюджет ~1100px)

| Колонка | Содержимое |
|---|---|
| Статус | бейдж (иконка+подпись); для running — с длительностью «идёт 4м» live |
| Даг | имя; ссылка на карточку (не на ран) |
| Дата данных | абсолютная (для manual = момент триггера) |
| Запущен | относительное время + триггер-бейдж (schedule/backfill/вручную) мелко |
| Длительность | — |
| ⋯ | Остановить (running, по правам); больше ничего |

`created_at` и «Создан» отдельными колонками не нужны: «Запущен» —
относительное; params-иконка уходит (params видны в ране). Строка → ран.
Авто-поллинг 10с. Пагинация — компактная, справа в подвале.

## 5. Ран (`/runs/[id]`) — главный экран продукта

**Назначение:** диагностика и управление одним выполнением.
**Главный вопрос:** где проблема и почему.
**Главное действие:** открыть лог нужного таска (1 клик или 0 — см. ниже).

### Каркас (1180px)

```
Navbar: ← Раны / <даг> / <id-короткий · copy> · статус-бейдж · длительность
        [Остановить] (running) · [обновить]
─ Контекст (однострочный грид, text-sm):
  триггер · дата данных · запущен · память max/Σ · образ (trunc+copy)
  [Параметры ▸]  [Окружение ▸]     ← раскрывашки, см. ниже
─ Граф (сворачиваемый; на узком экране свёрнут по умолчанию? — нет:
  высота ограничена 280px со скроллом внутри; состояние запоминается)
─ Таски (компактная таблица-список, вся ширина):
  статус · таск · попытка · старт(отн.) · длительность · память · [⋯]
─ Инспектор выбранного таска (панель, вся ширина, высота ~50vh):
  ┌ <таск> · статус · попытка N из M · exit reason ──────── [× закрыть]
  │ Табы: Лог | Попытки (N) | Артефакты (N) | Значения (N) | Env
  └ содержимое табы
```

- **Автовыбор таска:** при открытии failed-рана инспектор открывается на
  первом упавшем таске, таба «Лог» (реализация J1: 0 кликов до лога).
  running-ран — инспектор закрыт (виден граф+список), либо `?task=` из URL.
- Выбор таска: клик по строке или по узлу графа; выделение синхронно в
  обоих; `?task=` в URL.
- Таблица «Попытки» уровня рана — **удаляется**; «Значения» уровня рана —
  удаляется (живут в инспекторе; агрегата не нужно при типичных 1–5
  значениях).

### Инспектор: табы

- **Лог** — текущий RunLogViewer (фильтры, поиск, follow, скачивание) +
  переключатель попытки (если >1) + кнопка «на весь экран» → `/runs/<id>/log`.
  Для running-таска follow включён по умолчанию.
- **Попытки** — таба видна при >1 попытки: список `№ · статус · когда ·
  длительность · память · exit code/reason` (клик — лог этой попытки).
  При 1 попытке её exit-инфо и так в заголовке инспектора.
- **Артефакты** — `имя · размер · статус стрима (writing/committed/aborted)
  · [Превью] [Скачать]`; превью — текст первых ~64КБ в моно-блоке с
  пометкой обрезки. (*API-требование; до него табы нет*.)
- **Значения** — `ключ · значение (моно, раскрытие JSON) · обновлено`.
- **Env** — привязки таска из снапшота манифеста: `env-имя · тип
  (переменная/секрет) · источник (имя + скоуп: глобальный/даг) · значение`.
  Значение переменной — из снапшота рана (*API-требование*; fallback —
  текущее значение с явной пометкой «текущее, могло измениться после
  запуска»). Секрет — только имя и «••••» (ссылка в /env, где есть RBAC-
  кнопка показа).

### Раскрывашки контекста

- **Параметры** — JSON как сейчас (collapsible).
- **Окружение** — объединение env всех тасков рана (уникальные привязки),
  та же таблица, что в табе Env инспектора. Отвечает на «с каким конфигом
  шёл ран» без выбора таска.

### Состояния

- running: поллинг 3с; заголовок и статусы обновляются, инспектор
  сохраняет выбор и позицию лога (follow-логика уже есть).
- canceled: баннер «Ран остановлен. Успешные таски сохранены — ран можно
  доиграть ретраем таска» (обучение механике доигрывания).
- Ошибка загрузки — alert с retry. Таск pending/queued — инспектор
  показывает «ещё не запускался» + причину ожидания (зависимости из
  манифеста со статусами).

### Действия

- Остановить — в шапке (running, по правам), подтверждение как сейчас.
- Ретрай таска — в инспекторе и в «⋯» строки (завершённый ран,
  исполнявшийся таск), подтверждение с перечислением сбрасываемого
  подграфа (downstream-таски вычислимы из манифеста — показать имена).

## 6. Лог полноэкранный (`/runs/[id]/log`) — без изменений

Существующий вьювер силён; наследует всё. Добавить: `aria-label` кнопкам,
переключатель попытки в тулбаре (сейчас — только через URL).

## 7. `/env` — без структурных изменений

Мелкое: из инспектора таска приходить с `?q=<имя>` (подсветка найденного);
у секретов кнопка «показать» скрыта, если нет прав (сейчас — по клику
ошибка?) — проверить и не рендерить без прав.

## 8. `/pools` — минимальные изменения

Добавить занятость: `busy / slots` + мини-прогресс (данные есть в
dashboard RPC — *микро-требование к API: busy в ListPool*, либо тянуть
GetDashboard). Бейдж «пауза» при slots=0 — остаётся. Подсказка «таск
попадает в пул опцией loom.Pool(name)» — остаётся в модалке.

## 9. `/users` — без структурных изменений

Колонка «Создан» → относительное время; назначенные даги — бейджи как
сейчас, но при >5 сворачивать в «+N».

---

## Клавиатура (минимум, без command palette)

- Списки: строки фокусируемы, Enter — открыть (UTable/строки-ссылки).
- Ран: ↑/↓ по таскам при фокусе в списке, Esc — закрыть инспектор.
- Лог: `/` — фокус в поиск (уже привычно), End/Home — низ/верх.

## Что сознательно не делаем

- Bulk-операции (нет сценария), экспорт таблиц, тёмные/светлые
  кастомные темы (Nuxt UI уже даёт), realtime-websocket (поллинга
  достаточно на этих объёмах), graph-редактор.
