# 02 — Product Model

Концептуальная модель, на которой строится UI. Не копия схемы БД: модель
оператора, разбирающего раны.

## Типы объектов

| Объект | Тип | Жизненный цикл | Кто меняет |
|---|---|---|---|
| Даг | Entity + Configuration | living (обновляется из registry) | admin (регистрация/удаление), владелец (расписание/пауза) |
| Регистрация дага | Event (очередь) | pending → running → success/failed | система; инициатор — admin |
| Ран | Execution | running → success/failed/canceled | система; триггер/остановка — владелец |
| Таск (в ране) | Execution unit | pending → queued → starting → running → (up_for_retry →) success/failed/upstream_failed/canceled | система; ретрай — владелец |
| Попытка | Event (внутри таска) | starting → running → success/failed | система |
| Лог | Event stream (попытки) | пишется → закоммичен | только чтение |
| Артефакт | Data (выход попытки) | writing → committed/aborted | только чтение/скачивание |
| Значение (XCom) | Data (выход таска) | append/update | только чтение |
| Переменная/Секрет | Configuration (скоуп: глобальный/даг) | living | admin/владелец скоупа |
| Пул | Configuration + Status (busy/slots) | living | admin |
| Пользователь | Configuration | living | admin |

## Центральная ось (операционная иерархия)

```
Система (дашборд: что требует внимания)
  └── Даг (конфигурация + история выполнения + метрики)
        └── Ран (конкретное выполнение: контекст + прогресс)
              └── Таск (единица диагностики)
                    ├── Лог  ← сюда ведёт 80% визитов
                    ├── Попытки (если >1)
                    ├── Артефакты
                    └── Значения
```

**Ключевой принцип: единица диагностики — таск, не ран.** Всё, что
принадлежит таску (лог, попытки, артефакты, значения, env, метрики),
показывается вместе — в его инспекторе, а не отдельными таблицами уровня
рана. Ран отвечает на «что с выполнением в целом», таск — на «что
случилось здесь».

## Два лица дага

У оператора «даг» — два разных вопроса, и оба должна закрывать одна
карточка:

1. **Как он устроен** (статика): граф, таски, ресурсы, привязки env,
   расписание, образ. Нужна сразу после регистрации, до первого запуска.
2. **Как он себя ведёт** (динамика): последние раны, тренд длительности,
   память, «жирные» таски. Нужна постоянно.

Сегодня карточка показывает только (1). В новой модели динамика — первый
экран, статика — рядом (таба/секция), т.к. чаще смотрят поведение.

## Контекст рана

Ран — снапшот: манифест зафиксирован на момент запуска (`manifest_tasks`),
образ/digest зафиксированы. Значит и **окружение** (params, logical_date,
значения переменных, имена секретов) — часть снапшота рана и должно
показываться в ране, а не «где-то в /env». Значения переменных на момент
launch сегодня не фиксируются — требование к API; секреты в снапшоте —
только именами.

## Статусы

Три уровня статусов с разной семантикой; в UI они не смешиваются:

- **Ран**: running / success / failed / canceled — агрегат.
- **Таск**: полный жизненный цикл; `upstream_failed` — *следствие*, не
  ошибка (не выполнялся) — визуально приглушён; `up_for_retry` — переходное
  «ждёт» состояние.
- **Попытка**: техническая запись; наружу выносится только когда попыток
  больше одной или exit_reason важен.

Каждый статус = цвет + иконка + подпись (никогда только цвет).

## Права в модели

`canManageDag(dag)` — единственный предикат прав на действие. Правило UI:
**действия, недоступные пользователю, не рендерятся** (не disabled) — у
user-роли интерфейс просто спокойнее; исключение — контекст, объясняющий
пустоту (например, страница «Пользователи» вовсе скрыта из навигации).

## Каталог действий

| Действие | Объект | Риск | Кто | Подтверждение |
|---|---|---|---|---|
| Запустить ран (params) | Даг | низкий | владелец | нет (модалка — только для params) |
| Backfill | Даг | средний (N ранов) | владелец | да, с прогнозом числа ранов |
| Пауза/снятие | Даг | низкий, обратимо | владелец | нет |
| Расписание | Даг | средний | владелец | форма |
| Sync из registry | Даг | низкий | admin | нет |
| Auto-update on/off | Даг | низкий | admin | нет |
| Удалить даг | Даг | **высокий** | admin | да, с последствиями |
| Остановить ран | Ран | средний, полу-обратимо (доигрывается ретраем) | владелец | да |
| Ретрай таска | Таск | средний (сброс подграфа) | владелец | да, с описанием подграфа |
| Set/Delete env | Переменная/Секрет | средний (delete → launch_failed) | владелец скоупа | delete — да |
| Слоты пула | Пул | средний (0 = пауза пула) | admin | нет |
| CRUD пользователей | Пользователь | средний | admin | delete — да |
| Скачать артефакт | Артефакт | нет | любой аутентифиц. | нет |

## Чем UI-модель отличается от backend-модели

| Backend | UI |
|---|---|
| `attempts` — отдельная коллекция уровня рана | попытки — история внутри таска |
| `task_values` — отдельная коллекция | значения — свойство таска |
| переменные и секреты — два сервиса | одно env-пространство (уже сделано в `/env`) |
| регистрации — отдельная очередь | «состояние обновления» дага + короткая история на карточке |
| дашборд — один RPC с агрегатами | лента «требует внимания» + вторичные блоки |
| артефакты — data plane (artifact_v1) | файлы таска в инспекторе (через gateway-прокси, требование к API) |
