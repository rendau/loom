# 03 — Information Architecture

## Принципы

1. Плоская навигация: два клика от входа до лога упавшего таска.
2. Контекст не теряется: детали таска — инспектор внутри страницы рана,
   а не отдельные страницы; фильтры списков живут в URL.
3. Страницы соответствуют вопросам оператора, а не эндпоинтам.
4. Ширина 1180px — базовый вьюпорт: никакого горизонтального скролла
   страницы; широкое (лог, граф) скроллится внутри своего контейнера.

## Карта навигации

```
Сайдбар
├── Обзор                /            (дашборд «что требует внимания»)
├── Даги                 /dags        → /dags/[name] (табы: Обзор | Схема | Настройки)
├── Раны                 /runs        → /runs/[id]  (?task=…&tab=…)
│                                     → /runs/[id]/log (полноэкранный лог, как сейчас)
├── Переменные и секреты /env         (без изменений структуры)
└── Администрирование    (группа, admin видит всё, user — ничего из группы*)
    ├── Пулы             /pools
    └── Пользователи     /users       (admin only)
```

\* Пулы сегодня видны всем на чтение — остаются доступными по прямому URL
и с дашборда (блок пулов), но из сайдбара для user-роли уходят в группу
«Администрирование» только если он admin. Спорно → решение: пулы видны
всем (чтение полезно — «почему мой таск в очереди»), группа
«Администрирование» показывается user'у с одним пунктом «Пулы».

### Что меняется и почему

| Решение | Сейчас | Проблема | Станет | Trade-off |
|---|---|---|---|---|
| Дашборд → «Обзор» | набор равноправных блоков | не отвечает «что смотреть» | лента внимания (провалы/живые раны) + вторичные блоки + ёмкость volume | меньше «красивых» цифр |
| Карточка дага — табы | одна простыня «статики» | мониторинг не поддержан | Обзор (раны+метрики) / Схема (граф+таски+регистрации) / Настройки | +1 уровень (табы), оправдан двумя ролями карточки |
| Ран — master-detail | 4 блока-таблицы + slideover | диагностика через скролл и дубли | список тасков + инспектор таска (Лог/Попытки/Артефакты/Значения/Env) | сложнее layout; главный экран продукта — оправдано |
| Попытки/Значения | таблицы уровня рана | дубли, шум | внутрь инспектора таска | агрегатный взгляд «все значения рана» уходит на клик глубже — приемлемо |
| Действия в строках | до 8 иконок | шум, ошибки, ширина | 1–2 частых inline + меню «⋯» | частота нажатий чуть выше для редких действий |
| Группа «Администрирование» | плоский список | пулы/пользователи мешаются в основном потоке | отдельная группа сайдбара | — |

### Что сознательно НЕ меняется

- Маршруты `/env`, `/pools`, `/users`, `/login`, `/setup` — структура
  страниц остаётся (у `/env` уже хорошая механика фильтров-в-URL — она
  становится эталоном для `/runs`).
- Полноэкранный лог `/runs/[id]/log` — остаётся как «режим чтения».
- Отдельной страницы «Артефакты» не появляется: артефакт без контекста
  таска бессмыслен; volume-ёмкость — на Обзоре.
- Никакого command palette / глобального поиска: 27 дагов, 6 разделов —
  навигация и так короче, чем поиск.

## Глубокие ссылки (контракт URL)

Все состояния, на которые захочется дать ссылку коллеге, живут в URL:

| URL | Открывает |
|---|---|
| `/runs?dag=<name>&status=failed` | срез списка ранов (фильтры в query, как в /env) |
| `/runs/<id>?task=<t>` | ран с открытым инспектором таска `t` (таба по умолчанию — Лог) |
| `/runs/<id>?task=<t>&tab=artifacts` | конкретная таба инспектора |
| `/runs/<id>/log?task=…&attempt=N` | полноэкранный лог (как сейчас) |
| `/dags/<name>` | карточка, таба «Обзор» |
| `/dags/<name>?tab=schema` | схема дага |
| `/env?dag_name=…&kind=secret&q=…` | как сейчас |

## Контекстные переходы (швы между разделами)

- Обзор: провал → `/runs/<id>?task=<упавший>` (сразу в лог), живой ран →
  `/runs/<id>`, пул → `/pools`, даг → `/dags/<name>`.
- Список ранов: строка → ран; имя дага в строке → карточка дага.
- Карточка дага: ран из списка последних → ран; env-привязка таска →
  `/env?dag_name=…&q=<имя>`; «все раны» → `/runs?dag=<name>`.
- Ран: заголовок «даг / id» — имя дага кликабельно → карточка; таск в
  графе = таск в списке = один и тот же инспектор.
- Инспектор таска: «ретраится из» / attempt-переключатель — внутри.

## Иерархия внутри страницы рана

```
Шапка: даг / ран-id · статус · длительность · [Остановить] [⋯]
Контекст (одна строка-грид): триггер · дата данных · создан · образ ·
    память Σ/max · params (раскрытие) · env рана (раскрытие)
Граф (сворачиваемый, помнит состояние)
Таски (компактная таблица: статус · имя · попытка · длительность · память)
    → клик = инспектор
Инспектор таска (панель под/справа от списка):
    Лог | Попытки (если >1) | Артефакты | Значения | Env
```

На 1180px инспектор — нижняя панель во всю ширину (лог требует ширины);
на ≥1440px — правая панель. Выбор таска — `?task=` в URL.

## Правило детальности

- Списки отвечают «куда смотреть» — минимум колонок, статус первым.
- Карточки отвечают «что происходит с объектом» — сводка + переходы.
- Инспектор отвечает «почему» — вся глубина (логи, попытки, артефакты).
- Всё, что реже раза в неделю (digest, SDK-версия, история регистраций),
  не занимает места в списках — живёт в деталях.
